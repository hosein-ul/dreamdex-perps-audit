class="mb-8 flex flex-col gap-3"><p class="eyebrow text-[10.5px]">Somnia Markets / Reference</p><h1 class="display text-[36px] text-fg leading-[1.08]">Errors</h1></header><div class="prose-docs"><p>This page lists the error classes the SDK throws, the fields each carries, and the contract error names the SDK decodes into <code>ContractRevertError</code>. For the decision logic that goes with them, see <a href="/markets/somnia-markets/typescript/how-to/handle-errors">Handle errors and reverts</a>.</p>
<p>Every SDK error extends <code>SomniaMarketsError</code>, sets <code>name</code> to its class name, prefixes its message with <code>@somnia-chain/markets-sdk: </code>, and carries the underlying failure in <code>cause</code> when it wraps one.</p>
<h2 id="classes">Classes</h2>
<p>All classes are exported from the root entry.</p>
<p><code>FillHistoryRestartRequiredError</code> is returned by <code>getUserFillsPage</code> when a continuation belongs to a replaced serving dataset or is a legacy cursor without a generation. Its readonly <code>cursorGeneration</code> and <code>servingGeneration</code> fields identify the mismatch; legacy cursors report <code>&quot;legacy&quot;</code> as <code>cursorGeneration</code>. Discard accumulated pages and <a href="/markets/somnia-markets/typescript/reference/fill-history-pages">restart from page one</a>; retrying the old cursor cannot succeed. <code>getUserFillHistory</code> makes at most two attempts: its first read or refresh, then one full read when the first cannot stand. It throws this error when the dataset changes during that full read. Call it again.</p>
<p><code>FillHistoryUnavailableError</code> means the serving indexer has not initialized <code>FillDataset/current</code>. Deploy and reindex a compatible producer. Retrying the same deployment cannot make the contract appear.</p>
<p><code>PerpPositionChangesUnavailableError</code> means the serving indexer predates the <code>PerpPositionChange</code> table, so <code>listPerpPositionChangesForFills</code> has no position updates to pair fills with. Show each fill&#39;s own side until the indexer is reindexed by a compatible producer. Retrying the same deployment cannot make the table appear.</p>

<p>Errors from code the SDK calls but does not own can surface unchanged. This includes a <code>walletClient</code> supplied by the app and the client returned by <code>getViemClient()</code>. Debug sink failures are different: the SDK contains them so diagnostic code cannot break an operation.</p>

<p>A mined transaction with <code>status: &quot;reverted&quot;</code> carries no revert data. The SDK replays the call as <code>eth_call</code> at the receipt&#39;s block to recover <code>errorName</code> or <code>reason</code>. When the replay yields nothing, the error is still a <code>ContractRevertError</code> and its message ends with <code>(no revert data recoverable)</code>.</p>
<p><code>decodeRevert(caught)</code> is exported for callers who send transactions themselves. It walks the <code>cause</code> chain, decodes the first revert data it finds against <code>contractErrorsAbi</code>, and always returns a <code>ContractRevertError</code>. It does not check that the input is a revert: a transport error passed to it returns a <code>ContractRevertError</code> without <code>errorName</code>.</p>
